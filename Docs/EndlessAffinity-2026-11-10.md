## 2. 몬스터 계열 표 (`MonsterFamilies`, 명시 매핑)

계열은 이름, dropType, 직업으로 추측하지 않는다.

- 칵테일: 라임웨지, 레몬 브루트, 쉐이커 골렘, 올리브 바머, 스월스틱 컨저러, 마티니 스피릿(정예)
- 차: 티백 임프, 케틀 캐논, 슈가 큐브 바머, 리프 워든, 티 세리머니 가디언(정예), 새싹 찻잎 정령, 차시 궁수, 차 연구 정령(원두를 떨어뜨리지만 차 테마), 개완 수호자, 김 서린 주전자 장로, 차 화로 용
- 커피: 에스프레소 벅, 밀크 포머, 그라인더 골렘, 드립 서버 스펙터, 에스프레소 머신 리바이어던
- 중립: 진상 손님, 까다로운 차 손님(음료 테마가 아닌 손님)

## 3. 계열 스폰 테이블

- **정규 모드 표는 기존 규칙을 그대로 둔다.** 추첨 경로와 난수 소비 횟수도 바꾸지 않았다.
  - 바텐더: 칵테일 65 / 차 35. 2:30 이후에는 칵테일 64 / 차 34 / 커피 2.
  - 찻집: 차 100(2026-10-12 사용자 지시: 찻집에는 칵테일 몹이 나오지 않는다).
- **확인된 공백(보고):** 정규 찻집 런에는 칵테일 계열과 커피 계열의 일반 몹이 없고, 보스도 차 계열과 중립뿐이다. 그래서 정규 찻집에서는 차 음료(→칵테일)와 칵테일 음료(→커피)의 상성이 일어나지 않는다. 정규 바텐더 런에서 커피 계열은 2:30 이후 2%와 중간 보스 3종뿐이다.
- **끝없는 모드 표(코디네이터 결정 2026-11-10):** 직업과 관계없이 세 계열의 실제 몬스터를 낸다. 3웨이브마다 집중 계열이 커피 → 차 → 칵테일 순서로 바뀐다. 가중치는 집중 계열 70%, 나머지 계열 각 15%이고 정수 합은 100이다. 계열 안에서는 기존 시간 조건을 그대로 따른다. 차 계열은 찻집이면 찻집 트랙, 아니면 바의 차 트랙에서 뽑는다. 다음 집중 계열은 전환 1웨이브 전에 예고한다.
- 끝없는 모드의 음료 교체 기회는 **구현하지 않았다.** 저장 구조상 준비 음료 슬롯이 하나뿐이고, 출발할 때 그 한 잔을 마신다. 런 중에 바꿔 줄 다른 보유 음료가 없다. 교체를 넣으려면 새 소비 정책이 필요하므로 후속 결정으로 남긴다.

## 4. 음료 순환 상성

- 기준은 실제로 마신 음료다(`PlayerController.DrunkDrink`). 환불로 봉인된 동안에는 적용하지 않는다(`AffinityDrink`). 런이 끝나면 즉시 해제한다.
- 칵테일은 커피 계열, 커피는 차 계열, 차는 칵테일 계열에 추가 피해를 준다. 불리한 상성의 감소는 없고 중립은 0이다.
- 계산: B는 기존 계산(히든, 치명, 검 배율 등)이 끝난 정수 피해다. 상성이 맞으면 A = max(1, round(B×20/100))이고 반올림은 0에서 먼 쪽이다. 합계 T = B + A. **비율 20%는 조정할 수 있는 명세 기본값이다**(`DrinkAffinity.BonusPercent`).
- 적용 경로는 `Enemy.TakeDirectHit` 하나다. 근접 공격, 원래 투사체, 모카 증기 폭발(광역은 대상마다 따로)에 쓴다. 지속 피해, 반사, 파편, 처형에는 쓰지 않는다. TakeDamage를 두 번 부르지 않으므로 사망, 처치, 드롭 이벤트는 한 번만 일어난다. 무적이거나 피해가 0이면 숫자도 연출도 없다.
- 표시
  - 피해 숫자: `120 (추가 20)`. 보조 문구 `상성!`은 전역 1.5초 간격으로만 붙는다.
  - 출전 화면: 순환 상성 한 줄, 준비 음료 줄에 `커피 계열 추가 피해 +20%`.
  - 런 중: 효과 상세에 상성 줄. 첫 안내 배너에 `[커] 커피 계열 몬스터 추가 피해 +20%`처럼 글자 표식을 붙인다.

## 5. 보상 분리: 출처 장부(A안, 코디네이터 승인)

**왜 필요한가.** 스킨 재화는 `drinks.json`의 판매 코인(`coins`)이다. 런에서 직접 지급되는 경로는 없다. 하지만 런에서 받은 재료로 음료를 만들어 주문에 팔면(`DrinkLab.Sell`) 코인이 생기고, 이 코인으로 스킨을 산다(`BuyCosmetic`). 무한 모드 재료가 일반 재료와 같은 창고에 섞이면 이 경로로 스킨 재화를 우회 획득할 수 있다. 그래서 무한 모드 재료가 들어간 음료는 **마실 수는 있지만 판매할 수 없게** 했다.

- `drinks.json` v4
  - `endlessStock`: 재료별 무한 출처 양. 항상 0 ≤ 무한 출처 ≤ 재고.
  - `prepared.endlessAmounts`: 이 음료를 만들 때 쓴 무한 출처 양.
  - `pending[].endless`: 무한 런 보상 표시.
- 정산: 정상 종료와 비정상 종료 복구 모두 보상의 `endless` 표시를 보고 재고와 장부에 같은 양을 더한다. 중복 정산은 기존 `settledRunIds`가 막는다.
- 제조: 재료별로 일반 출처를 먼저 쓰고, 모자란 만큼만 무한 출처를 쓴다. 무한 출처가 1 단위라도 들어가면 판매할 수 없다. 제조 전에 영수증 하단에 미리 알린다.
- 판매: 거래 안에서 다시 검사한다. 거부하면 코인은 0이고 음료, 재료, 주문은 그대로다. 재로드한 뒤에도 같다.
- 제조 취소 환불: 기록해 둔 출처 그대로 되돌린다. 버리기, 보존 포기, 소모는 기존 규칙을 따른다. 판매 가능 여부는 제조 시점에 정해진다.
- 원자성: 모든 변경은 기존 `Transact`(복제본 → 저장 성공 시 교체)로 처리한다. 저장에 실패하면 재고와 장부가 함께 되돌아간다.
- StockMax 초과: 무한 출처는 클램프 뒤 실제로 늘어난 양만 장부에 적는다. 재고가 장부 밖의 경로로 줄면 무한 출처부터 줄인 것으로 본다. 판매할 수 있는 양을 늘리지 않는 쪽을 택했다.
- 마이그레이션: v3 이하 파일은 값을 바꾸지 않는다. 장부가 비어 있으므로 기존 재고와 기존 준비 음료는 모두 일반 출처이고, 지금처럼 판매할 수 있다. 처음 읽을 때 원본을 `drinks.json.pre-ledger-v{n}.bak`으로 한 번 복사한다. 버전을 4로 올렸기 때문에 구 빌드는 v4 파일을 미래 버전으로 보고 쓰지 않는다. 장부가 사라지는 것을 막기 위한 조치다.
- 막지 않는 것: 무한 모드의 재료 획득, 제조, 음용, 연구 포인트. 기존 코인, 이미 산 스킨, 기존 재고. 공유 코드(레시피만 담고 재고나 음료는 담지 않는다).
- 다른 재화가 코인으로 바뀌는 경로를 찾아봤다(`coins` 증가 검색). 증가는 `DrinkLab.Sell` 하나뿐이다. 연구 포인트와 스페셜티는 코인으로 바뀌지 않는다. 끝없는 모드에서는 보스 클리어 보상인 스페셜티도 지급하지 않는다(`GrantSpecialty` 가드).
