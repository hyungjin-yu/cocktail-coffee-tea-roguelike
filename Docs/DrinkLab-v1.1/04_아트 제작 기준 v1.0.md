# 아트 제작 기준 v1.0 — Codex 제작 / Claude Unity 적용

> **전체판 연결:** [[05_게임 완성 명세 v1.0]]이 전체 범위, [[06_전투와 런 규칙 v1.0]]이 게임 동작, [[09_완성판 아트 사운드 명세 v1.0]]이 추가 아트의 기준이다. 본문의 355프레임은 기본분이며 완성판은 09의 진상 손님 8프레임을 더한 **363프레임**이다. (2026-09-25 갱신: 커피 일반 몹 2종을 정식 범위에 포함하며 321/329 → 355/363으로 분모 갱신 — §2/§11 참고)

## 1. 이 문서의 역할과 결정 근거

사용자 목표: 기획과 디자인을 먼저 완성하고, Codex가 2D 스프라이트를 제작하며 Claude가 Unity에 적용한다.
사용자 확정(2026-09-23): **기존 픽셀 아트를 유지하고 벨트스크롤 시점으로 통일한다.**

이 문서는 현재 게임의 아트를 완성하는 단일 제작 기준이다. 00은 게임 전체 기획, 01·02는 로스터와 동작, 03은 이 명세를 이미지 생성 요청으로 전달하는 문서다. 충돌 시 최신 사용자 지시가 최우선이고 전체 범위는 05, 게임 규칙은 06~08, 확장 아트는 09, 기본 외형은 본 문서를 따른다. 01·02·99는 확인한 기존 구현/이력이다. 실제 동작·수치의 현황은 확인한 코드가 기준이며, 새로 제안한 디자인과 구현 완료 사실을 혼동하지 않는다.

이하 구체적인 외형·색상·규격은 기존 설정을 연결해 작성한 **제작 기본값**이다. 사용자가 세부 항목 각각을 승인했다는 뜻은 아니다. 작업자는 이 기본값을 따라 제작하고 임의로 다른 디자인을 추가하지 않는다. 나중의 명시적 사용자 변경은 새 버전에 기록한다.

디자인 고정과 생성 품질은 별개다. AI가 명세와 다른 손·소품·시점·프레임을 만들면 같은 디자인으로 보정한다. 문서만으로 최초 출력의 무수정 사용을 보장하지 않는다.

## 2. 제작 범위 고정

이 문서는 기존 v0.2를 기반으로 한 **기본 아트 사양**이다. 실제 제작 범위는 05의 게임 완성판이며 하이브리드와 최종보스 추가 패턴은 09에 확장되어 있다. Steam 업로드는 범위 밖이다.

- 플레이어 2종: 바텐더, 티 소믈리에. 직업별 몸체 하나에 해당 무기 2종을 교체 장착.
- 일반/엘리트 적 13종: 칵테일 6종(레몬 브루트 포함), 차 5종, 커피 일반 몹 2종(에스프레소 벅, 밀크 포머).
- 보스 4종: 그라인더 골렘, 드립 서버 스펙터, 에스프레소 머신 리바이어던, 진상 손님.
- 기존 무기 4종, 재료 3종, 영구 강화 아이콘 6종은 우선 재사용. 실제 파일 품질과 연결 여부만 검수.
- 단일 카페/바 스테이지 배경, 전투 VFX, 공용 UI 장식과 상태 아이콘을 포함.
- 하이브리드 무기와 진상 손님의 신규 2패턴은 **09에 정의된 필수 추가 범위**다. 추가 직업/스테이지, 카드별 고유 일러스트는 제외한다.
- **커피 일반 몹 2종은 2026-09-23에 실제 아트가 나오면서 사용자가 이번 범위에 포함하기로 결정했고(99 로그 참고), 코드에도 이미 구현·연결돼 있다. 이 문서가 2026-09-23 최초 작성 시 이를 반영하지 못했던 게 뒤늦게 드러난 문서 격차라 2026-09-25에 정정했다** — §5 표/§6 프레임 총계/§11에 반영.
- 재료 품종 18개는 현재처럼 종류별 공용 아이콘을 공유한다. 이름 차이만으로 18개 이미지를 추가 생성하지 않는다.

완료 범위 밖에 있는 기능 때문에 현재 캐릭터 외형을 바꾸지 않는다. 09에 없는 미래용 무기·장식을 몸에 미리 그리지 않는다.

## 3. 공통 시각 규칙

### 시점·방향

벨트스크롤용 지면 높이의 3/4 측면. 기본 이미지는 화면 오른쪽을 바라본다. 몸의 앞면과 옆면은 보이되 머리 윗면은 조금만 보인다. 탑다운, 아이소메트릭, 위에서 내려다보는 쿼터뷰는 사용하지 않는다. 화면 위/아래 이동은 레인 이동이며 뒤통수·정면 전용 세트를 추가하지 않는다.

좌향은 이미지와 손잡이 좌표를 함께 반전한다. 글자·숫자·로고처럼 반전하면 의미가 깨지는 정보는 스프라이트에 넣지 않는다. 물체의 물리적인 좌우 장식은 화면 방향에 맞춰 함께 반전해도 된다.

### 스타일·광원

기존 몬스터의 굵은 어두운 윤곽선, 작은 몸통/큰 특징물, 덩어리 중심 픽셀 표현을 유지한다. 새로 실사풍·매끈한 벡터풍·3D 렌더풍으로 바꾸지 않는다. 재질당 기본/그림자/하이라이트 3단계를 사용한다. 광원은 화면 왼쪽 위이며 새 애니메이션에서 재질과 명암 단계가 바뀌지 않는다.

기존 1024px 아트는 외형 기준 원본이다. 진짜 64×64 도트와 같은 이미지라고 가정하지 않는다. 신규 납품은 아래 규격으로 정리하지만 기존 원본을 덮어쓰거나 단순 축소만으로 품질 합격 처리하지 않는다.

## 6. 애니메이션 명세

본체/무기/바닥 그림자/VFX를 분리한다. 몸체에 그림자·발사체·장판·문자를 그려 넣지 않는다. 모든 프레임의 머리 크기, 장식 개수, 발 기준점이 일정해야 한다.

| 클립 | 프레임 / 속도 | 포즈 규칙 |
|---|---|---|
| idle | 4 / 6 fps, 반복 | 기준→미세 상승→기준→미세 하강. 전체 높이 변화 최대 본체 높이 2% |
| move | 6 / 10 fps, 반복 | 접지→하중→중간→반대 접지→반대 하중→중간. 이동은 Unity가 담당, 이미지가 캔버스 안에서 옆으로 이동하지 않음 |
| action | 4 / 12 fps, 1회 | 준비→동작 직전→실행 포즈→복귀. 투척은 팔/주둥이만 움직이고 발사체는 분리 |
| hurt | 1 / Unity 0.08초 표시 | 몸이 약간 움츠러든 포즈. 색상 플래시는 Unity가 적용. 게임 조작/공격 중단 없음 |
| defeat | 4 / 10 fps, 1회 | 힘 풀림→접힘/깨짐→무너짐→잔해. 고어 없음. 보상과 판정 제거는 기존 사망 시점 유지 |

- A(플레이어): idle 4 + move 6 + melee 4 + ranged 4 + hurt 1 + defeat 4 = **23프레임/직업**. melee/ranged는 action 타이밍 사용. 손잡이 좌표는 프레임마다 매니페스트에 제공한다. 직업별 가능한 두 무기만 연결.
- R(이동·접촉 적): idle 4 + move 6 + hurt 1 + defeat 4 = **15프레임/종**. 별도 공격 준비로 접촉 판정을 늦추지 않는다.
- T/E: idle 4 + move 6 + action 4 + hurt 1 + defeat 4 = **19프레임/종**.
- S: idle 4 + action 4 + hurt 1 + defeat 4 = **13프레임/종**. 제자리 소환이므로 move 없음.
- B 공통: idle 4 + move 6 + hurt 1 + defeat 4 = **15프레임/종**, 아래 전용 action 추가.
- 그라인더: charge_prepare 4, charge 2(반복) → 총 21. 현재 0.8초 예고와 0.6초 돌진 구간에 클립을 맞춘다.
- 드립: drip 4, vanish 4, appear 4 → 총 27. appear는 vanish 역순 재생 가능하되 별도 클립 이름은 유지.
- 머신: steam 4, rain 4, pressure 4 → 총 27. 압력 증가·발사 시점은 로직이 권한을 가진다.
- 진상 손님: refund 4, summon 4 → 총 23. 분노는 동일 클립+오버레이로 처리한다.
- **일반/엘리트 종 구성(2026-09-25 갱신, 커피 2종 포함)**: R 6종(lime_wedge, lemon_brute, olive_bomber, teabag_imp, sugar_cube_bomber, espresso_bug) × 15 = 90. T 3종(shaker_golem, kettle_cannon, milk_foamer) × 19 = 57. S 2종(swirl_stick_conjuror, leaf_warden) × 13 = 26. E 2종(martini_spirit, tea_ceremony_guardian) × 19 = 38. 합계 90+57+26+38 = **211프레임**.
- 전체 몸체 범위: 플레이어 46 + 일반/엘리트 211 + 보스 98 = **355프레임(기본분)**. 09의 추가 8프레임을 포함한 최종 몸체 납품은 363프레임이다. 좌향 복제, 별도 VFX, 반복 참조 프레임을 신규 그림 수에 중복 계산하지 않는다.

프레임 제작 순서: 모든 개체의 idle_00 외형 기준 → 이동/대기 → 필요한 공격 → 피격/사망. 같은 개체를 매 프레임 새 텍스트만으로 생성하지 말고 기준 프레임을 이미지 참조로 사용한다.

**동작 권한:** 이미지의 3번 프레임을 이유로 피해·발사·소환 시간을 바꾸지 않는다. 06에서 정한 최종 게임 이벤트가 클립을 재생하고, 빠른 공격 속도에서는 클립을 단축하거나 다시 시작한다. 예고가 있는 보스는 06의 예고 시간에 맞춘다. 사망 연출은 판정 없는 시각 오브젝트에서 재생한다.

## 7. 캔버스·좌표·파일 계약

신규 몸체: 일반/플레이어 256×256, 보스 512×512 RGBA PNG, sRGB.
권장 정리 단위는 일반 2×2px, 보스 4×4px. 이는 같은 화면상 픽셀감을 위한 기준이며 이미지 생성기가 정확한 격자를 지켰다는 보장은 아니다. 흐릿한 가장자리·불규칙 선을 검수하고 정리한다.

- 기본 방향 right. 왼쪽은 반전 재생.
- 피벗: 정규화 (0.5, 0.125). 일반 (128,32), 보스 (256,64), **좌하단 원점**.
- 지면형 발 접지선 y=32/64. 부유형은 같은 좌표를 바닥 기준으로 두고 몸을 그 위로 띄운다.
- 본체 목표 최고점 y=224/448, 좌우는 16..239 / 32..479 안에 둔다. 위아래 범위를 넘는 안테나·끈은 본체 높이에 포함해 맞춘다.
- 본체와 동일 피벗의 전체 크기 캔버스를 유지. 프레임별 자동 잘라내기 금지.
- 접지 이동 허용: 기준 포즈의 뒷발/앞발 변화는 가능하지만 두 발이 모두 떠서 기준면이 미끄러지지 않게 한다.
- 독립 VFX는 128×128 또는 장판 256×128, 중심 피벗. 총구/손 위치 등 별도 anchor는 좌하단 원점 픽셀 좌표로 기록한다.
- 배경 없음은 **실제 알파 0**을 뜻한다. 바둑판, 흰 배경, 회색 헤일로를 그려 넣지 않는다. 출력 해상도/알파가 다르면 생성 원본으로만 보관하고 납품 규격으로 합격 처리하지 않는다.
- 원본, 기준 프레임, 정리된 납품본을 별도 보관한다. 생성 모델의 출력 크기 제약을 프롬프트의 숫자만으로 해결했다고 가정하지 않는다.

Codex 작업 폴더(향후 생성):
ArtSource/v1/<asset_id>/reference/
ArtSource/v1/<asset_id>/frames/<asset_id>_<clip>_right_<00..>.png
ArtSource/v1/<asset_id>/preview.png
ArtSource/v1/<asset_id>/manifest.json

preview.png는 연락용 컨택트 시트이며 Unity가 자동 임포트할 파일이 아니다.
각 클립 프레임 파일은 위 표의 수량과 일치해야 한다. 별도 좌향 PNG는 만들지 않는다.

manifest.json 필수 필드:
- specVersion: "1.0", assetId, status: "ready" 또는 "needs_fix".
- sourceReferences: 실제 참조한 기존 이미지 경로 목록.
- frameSizePx: [256,256] 또는 [512,512], pixelsPerUnit: 128.
- pivotNormalized: [0.5,0.125], targetBodyHeightWorld: 표의 H.
- bodyHeightPx: idle_00에서 기준면부터 최고 본체 픽셀까지 실제 측정값.
- clips: 이름별 fps, loop, files 순서 목록.
- anchorsByFrame: 손/총구/활 화살 위치. 무기 없는 개체는 빈 객체. 좌하단 원점.
- deviations: 명세와 다른 점 목록. 합격하려면 기능·외형 차이가 없어야 한다.
- 검수 항목별 결과와 검수한 이미지 목록. 확인하지 않은 사항은 통과로 적지 않는다.

## 8. 무기·재료·VFX·UI·배경

### 기존 아이콘과 무기

Weapons/rapier.png, gun.png, sword.png, bow.png의 형태/색을 유지한다.
몸체에 무기를 합성하지 않는다. 레이피어·검은 손잡이에서 오른쪽으로 칼날, 총은 오른쪽 총구, 활은 오른쪽 발사 방향으로 정리한다. 회전/반전은 손잡이 기준. 각각 전체 길이 목표는 플레이어 높이 대비 레이피어 0.8, 검 0.65, 총 0.4, 활 0.7. 이는 시각 길이이고 사거리/히트박스가 아니다.
무기 아이콘은 기존 UI 파일 유지, 장착용 변형이 필요하면 weapon_<id> 이름으로 별도 납품한다. 총알/화살은 본체와 별도.

재료: cocktail_ingredient(칵테일), tea(차), coffee_bean(원두) 재사용.
영구 강화 6종도 현재 연결 유지. sturdy_tumbler 표시명은 **아이스음료의 필수품**, skilled_roasting은 **정확한 계량**. 아이콘 때문에 표시명·효과·저장 ID를 바꾸지 않는다.
스페셜티는 현재 강화 보스 처치 즉시 저장/획득하는 재화다. 새로운 줍기 오브젝트를 만들지 않는다. UI용 아이콘만 황금 테두리 원두 메달(128×128, 이름 specialty)로 제작한다.

### 배경

주제는 하나의 야간 카페 겸 바. 왼쪽/오른쪽 이동 구간마다 테마를 바꾸지 않는다.
- cafe_wall: 1024×512, 가로 반복 가능한 어두운 목재 벽(#3B3035), 상단 병 선반과 차통. 글자/로고 없음. 바닥과 분리.
- cafe_floor: 512×256, 가로·세로 반복 가능한 낮은 대비 목재 바닥(#695346). 위험 장판처럼 보이는 원형 무늬·균열 없음.
- cafe_counter: 512×256, 벽측 장식용 카운터. 이동 레인 안에 장애물로 두지 않음.
- cafe_lamp: 128×256, 크림색 작은 벽등. 번쩍임 없이 고정.
모든 배경은 좌우 끝 접합 검수. 캐릭터보다 낮은 채도/명암 대비. 이번 범위에 실내외 전환·새 충돌벽·전경으로 플레이어를 가리는 가구 없음. 카메라와 이동 레인의 기존 범위를 유지한다.

### UI

게임 UI의 글자는 Unity 텍스트로 표시한다. 카드명·수치·확률·한글을 그림에 생성하지 않는다.
공용 제작: ui_panel(256², 모서리 16px 9-slice), ui_card_frame(256×384, 모서리 16px 9-slice), ui_button(256×64, 모서리 12px 9-slice).
재질은 진한 목재 바탕, 아이보리 얇은 테두리, 선택 상태 청록 테두리. pressed/disabled는 Unity tint. 카드 희귀도는 색과 텍스트 라벨을 함께 유지.
상태 아이콘(각 128², 1프레임): status_slow=꿀방울 속 발자국, status_suppressed=사선이 그어진 상승 화살표, status_invulnerable=얇은 유리 방패.
직업 선택 초상화는 각 idle_00을 잘라 재사용한다. 결과 화면은 기존 재료/직업 아이콘을 사용한다. 카드별 삽화·개별 스킬트리 배경은 추가하지 않는다.
정식 게임명은 미정이지만 이미지에 제목을 넣지 않으므로 제작을 막지 않는다.

## 9. Claude Unity 적용 계약

이 절은 새 아트 적용 요구사항이며 현재 구현 완료 사실이 아니다. 현재 프로젝트의 구조를 존중해 필요한 연결만 수정한다.

- Codex 소유: ArtSource/v1 아래 이미지·manifest·검수 보고. Unity C#·씬·프리팹·.meta는 수정하지 않는다.
- Claude 소유: Unity Assets, 임포트 설정, 애니메이션/렌더링 연결, 테스트. 원본 디자인을 임의로 다시 그리거나 본체 비율을 비균일 확대하지 않는다.
- ready인 에셋만 ArtSource에서 Assets/_Project/Art/v1로 복사해 적용한다. 복사는 Claude가 수행. 기존 Resources 경로는 연결을 교체하기 전까지 보존.
- 새 PNG는 Single Sprite, 128 PPU, Point 필터, mipmap off, 압축 없음, RGBA 알파 유지. 여러 PNG로 클립 구성. 기존 .meta의 GUID를 불필요하게 새로 만들지 않는다.
- **128 PPU만 변경하면 안 된다.** 현재 Enemy는 1024px/1024PPU 전제를 포함한 공통 2배 확대를 사용한다. 새 개체는 별도 Visual 자식에 다음 식으로 균일 배율 적용:
  visualScale = targetBodyHeightWorld / (bodyHeightPx / pixelsPerUnit).
  공통 EnemyIconVisualScale을 추가 곱하지 않는다. 기존 에셋은 기존 경로를 유지해 단계적으로 전환한다.
- 물리 루트의 위치·반지름·공격 판정·이동 속도는 보존한다. 새 발 피벗으로 전환할 때 시각 위치만 보정한다. 플레이어는 현재 루트 자체에 스케일/방향 반전을 하므로 Visual 분리가 필요하다. Physics 스케일 변경을 아트 적용에 섞지 않는다.
- 좌우는 Visual과 손 anchor만 반전. 체력 UI·문자는 반전하지 않는다.
- y 깊이 정렬은 발 기준으로 통일. 부유형의 바닥 기준점은 몸 흔들림과 분리한다. 그림자→장판→개체→공중 효과→HUD 순으로 가독성을 확보하되 실제 프로젝트 정렬 체계에 맞춰 적용한다.
- 무기, 탄환, 보스 VFX의 실제 피해/사거리/속도는 06/07의 최종 규칙 기준. 애니메이션으로 밸런스를 재정의하지 않는다.
- 시각 상태/클립 데이터는 별도 설정으로 제공할 수 있으나 EnemyDef를 전부 새로운 MobData 구조로 갈아엎는 작업은 이번 범위에 포함하지 않는다.
