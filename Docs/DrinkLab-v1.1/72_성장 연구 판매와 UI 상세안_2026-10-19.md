# 성장·연구·판매·UI 상세안 — 2026-10-19

사용자의 “정하자”에 따라 미정 항목을 연결한 구현 기본안. 사용자 확정 방향은69, 아트 수량 규칙은04를 따른다. 아래 수치는 설계를 구체화하기 위한 최초 밸런스이며 실측 결과가 아니다. 플레이 검증으로 조정 가능하다. 현재 구현 중단은 유지하며 이 문서 작성은 개발 재개가 아니다. GitHub 반영은 아직 하지 않았다.

3. 재료 수급 확장 및 노트북의 스킬/직원 연구.
4. 주문 판매와 외형 상점. 완성 음료의 직접 사용/판매 선택.

### 보유량 보정

추첨 직전 e=(창고 잔량+현재 런 미정산 획득량)/d. 기준 사용량 d는 위 표이며 유저가 편집하는 레시피에서 가져오지 않는다. 배합에만 올려놓은 미소모 재료는 창고에 포함, 이미 소비해 완성 음료가 된 재료는 제외.

`multiplier = 1 + 0.5 × clamp((3-e)/3, -1, 1)`

0회분은×1.5, 3회분×1, 6회분 이상×0.5. 최종 확률은 기본 가중치×multiplier를 전체 후보 합으로 나눔. 기본0은0 유지. 여러 묶음은 앞 추첨 획득분을 다음 추첨에 반영. 전체 몬스터 난수와 독립된 런 제조 보상 난수/보상 ID 사용, 저장 재시도로 재추첨하지 않는다. 보유량의 확률 영향과 획득처를 도감에 설명. 고의 소진 유도/편중은 검증 대상이며 완전 차단을 주장하지 않는다.

맵 외형은 드랍표에 영향을 주지 않는다. 테마별 파밍 차이는 향후 별도 게임 모드로 명시 승인될 때만 검토.

## 6. 음료 판매와 외형 구매

제조 확정은 재료를 한 번만 소비하고 고유 ID의 완성 음료1개 생성. 기존 준비 음료 슬롯1개를 유지. 완성 후 ‘출발용으로 준비’ 또는 ‘주문에 판매’ 선택. 기존 준비 음료가 있으면 먼저 사용/판매/명시 폐기해야 다음 제조 확정 가능하며 자동 덮어쓰기 없음. 판매는 완성 음료를 소비하고 코인을 같은 거래로 저장. 직접 사용·판매 중복 불가. 배합/레시피 저장은 음료 아이템 생성이 아니다.

동시 주문3개. 주문마다 음료 계열, 지정 재료2개와 최소량(각 기준 사용량d의50%), 기법, 색 계열을 표시. 핵심 조건은 계열+지정 재료량, 맞으면 판매 가능. 기법/색은 선택 보너스. 색은 구현된 최종 색 모델을 단일 기준으로 판정하고 제조 전에 일치 여부 표시. 주문은 완성 음료의 성분/기법 스냅샷으로 판단한다.

- 기본 판매100코인, 기법 일치+25, 색 일치+25. 최대150. 재료를 많이 넣거나 치명타 버프를 크게 만든다고 가격이 더 오르지 않는다.
- 주문 취소는 무료, 해당 칸은 다음 런 종료 시 새 주문 제공. 보상 없는0~4킬 포기로는 갱신 안 됨. 주문 완료 시 즉시 다음 주문1개 제공. 시간 제한 없음.
- 보유/발견한 재료와 실제 쓸 수 있는 기법에서만 주문 생성. 최초에는 홍차/녹차/진/레몬 등 기본 조합으로 만들 수 있는 주문을 최소1개 제공. 상호 모순/용량 초과/중복 지정 재료 금지.
- 테스트 지급 재료/개발 명령은 격리 저장에서만 사용하며 실제 판매 재화로 반출 불가.

초기 외형 기준 가격: 캐릭터 스킨1000코인, 무기 스킨800, 맵 외형1500. 등급별 유료 뽑기 없음. 이 확장에서 제작하는 모든 외형은 플레이 코인 경로 제공. 기존 유료 SKU/소유권은 유지하고 연결 정책을 별도 검토, 무단 상품 변경 없음. 최초 구매 목표는 약6~10잔 수준이나 실제 드랍/주문과 함께 시간 실측 필요. 맵은 충돌·스폰·드랍·난도·길 찾기 정보를 바꾸지 않는 시각 변경.

## 7. 화면과 모션

### 제조

재료는 작은 종이 정보 카드, 중앙은 제조 도구, 오른쪽 영수증은 현재 배합/계량 중 양/기법/예상 효과. 계량 중 수치 갱신, 투입 완료 줄 확정. 주요 제조 버튼 고정, 길어진 내용만 스크롤. 장식보다 읽기/비교/조작 우선.

레시피 저장 시 이름 입력→스프링 노트에서 종이 한 장 찢기→레시피 보관함. 저장 트랜잭션 성공 후 연출, 실패하면 저장 성공처럼 찢지 않는다. 재사용/수정/공유 버튼. 찢기0.5초 초기값, 반복 시 건너뛰기. 실제 음료/재료를 중복 생성하지 않는다.

### 노트북

손 없이 닫힌 노트북 등장0.25초→덮개 열기0.35초→화면 점등0.15초. 총0.75초 초기값. 반복 시 클릭/Enter로 끝 상태 이동. 닫기0.35초. 열기/닫기 중 중복 입력 및 이중 거래 차단. 열린 상태에서만 내부 버튼 사용.

상단 ‘기존 강화 / 숙련 트리 / 직원 채용’. 트리는3가지의 경로를 탭으로 탐색하며 상세 영역과3장착 슬롯 표시. 직원은 칵테일/차 두 열을 한 화면에서 비교, 선택 후 상세와 채용 버튼. 마우스/키보드/터치 지원,720p에서 본문 실제18px 이상·터치 영역44px 이상 목표. 전체를 축소해 맞추지 말고 콘텐츠 스크롤 사용. 재화 잔액·구매 조건·소유/장착 상태를 숨기지 않는다.

## 8. 검증과 조정

기획 확정과 구현/밸런스 합격을 구분. 재개 시 기존24종/직업/히든 효과와 새12종 조건을 소스 기준 대조 후 중복 또는 미지원 발동 조건은 구현 전에 수정 기록. 오래된 전체 테스트 통과를 새 기능 결과로 재사용하지 않는다.

드랍 시드 반복의 편중·부족 재료 보정·보스 희귀보장·중복정산을 검증. 0/4/5킬, 사망/클리어/강제종료/저장실패, 채용/해금/판매 이중 클릭 및 재시작을 검사. 기존 RP 없는 저장·unknown ID·기존 유료 외형 소유 보존. 일반/숙련 진행 계정에서 한 잔까지 걸린 판 수·첫 외형 구매 시간·연구 선택 분포를 기록하고 초기 수치를 조정한다.

## 추가 확정: 노트북 뒤 직업별 공간 배경

사용자가 노트북을 닫을 때 뒤가 검은색인 점을 지적했다. 노트북 등장·열기·점등·사용·닫기·원래 화면 복귀 전과정에서 바텐더는 바 카운터, 티 소믈리에는 차 테이블 공간이 보여야 한다. 노트북이 실제 작업대 위에 놓인 구도로 만들며 닫는 순간 검정 flash도 없어야 한다. 기존 적합한 카페/바/차 아트를 재사용하고 입력 차단용 패널과 배경 그림을 분리한다. 직업/종류 변경·좁은 창·건너뛰기·화면 복귀 포커스와 입력도 검수한다. 아직 구현·시각 검증 완료는 아니다.
