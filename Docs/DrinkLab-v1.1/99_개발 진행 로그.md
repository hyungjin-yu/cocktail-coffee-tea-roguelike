## 2026-09-28 — 키보드 전용 내비게이션 (G31 완료, Codex 작업과 무관)

- **08:50 "마우스 hover와 키보드 focus는 같은 [강조]"**: Unity Selectable은 마우스 hover(Highlighted)와
  키보드/게임패드 포커스(Selected)를 서로 다른 색으로 다루는데, 이 코드베이스 전체가 highlighted/pressed
  색만 맞춰두고 selected는 기본값(사실상 무늬 없음) 그대로였다 — 키보드로만 다니면 지금 뭐가 선택됐는지
  전혀 안 보이는 상태. `UiFactory.ApplyHoverColors(button)` 하나로 세 색(highlighted/selected/pressed)을
  통일하는 공용 헬퍼를 만들고, 각 화면에 흩어져 중복돼 있던 색 설정 코드를 전부 이 호출 한 줄로 교체했다

  아예 hover 색 자체가 없던 것도 같이 발견해서 고쳤다).
- **처음 진입 시 아무것도 선택 안 됨**: 화면이 열려도 `EventSystem`에 아무 것도 선택돼 있지 않아서, 마우스

  안내, 제작 정보) 전부의 `Show()`/`Create()` 끝에 `EventSystem.SetSelectedGameObject`로 기본 항목을
  넣었다. 확인창 계열(Pause의 런 종료 확인, 설정의 해상도 확인)은 08:100 "취소 기본 포커스"와 같은
  원칙으로 안전한 선택지(취소/되돌리기)를 기본으로 뒀다(타이틀의 종료 확인창은 이미 이 세션 초반에

## 2026-09-28 — Pause 복귀 1초 카운트다운 (08:102, Codex 작업과 무관)

"더 해" 요청에 이어 08:102를 코드로 다시 훑다가 발견한 명세 갭: "재개는1초 '계속' 카운트다운 동안
이동·피해정지, 이후 Playing. 선택화면으로 돌아갈 때 카운트다운 없이 그 화면 복원." — 지금까지 `ClosePause`
는 Playing으로 복귀할 때도 그냥 즉시 `Time.timeScale=1f`였음.

- `GameManager.ClosePause()`: Playing으로 돌아갈 때만 `resuming=true` 세우고 화면 중앙에 "계속..." 오버레이
  (`PauseView.ShowResumeCountdown/HideResumeCountdown`, Pause 메뉴 자체와 별개 오브젝트라 Pause가 숨어도
  보임)를 띄운 채 코루틴(`ResumeAfterCountdown`, `WaitForSecondsRealtime(1f)` — timeScale이0인 동안이라
  실시간으로 재야 함)으로1초 기다린 뒤에야 `Time.timeScale=1f`. 선택 화면(LevelUp 등)으로 돌아갈 땐 원래대로

#### 3차 시도(진짜 원인 발견): 내가 만든 알파 채널 자체가 체커보드로 깨져 있었음

**진짜 원인**: 원본 몹 아트의 "흰 배경"이 균일하지 않고 비네팅/노이즈가 있었음 (코너 샘플링해보니 밝기가 229~255 사이로 들쭉날쭉). 1차 수정 때 쓴 고정 임계값(248) + 좁은 페더(20) 방식이 이 편차를 감당 못해서, 경계값 근처 픽셀들이 알파 0/255 사이를 픽셀 단위로 왔다갔다 하며 체커보드 노이즈가 생김.

**수정**: 단순 임계값 대신 **이미지 테두리에서부터 플러드필**(연결된 무채색·고휘도 영역만 배경으로 인정)하는 방식으로 교체. 검은 테두리로 둘러싸인 캐릭터 내부의 흰색/회색 디테일(치아, 금속 하이라이트 등)은 배경과 연결되지 않으므로 안전하게 보존됨. 원본 소스(`Desktop\개발\커피칵테일차\이미지`)에서 5장 다시 처리 → 알파 시각화 이미지로 체커 노이즈 사라진 것 직접 확인, 회색 비중 큰 쉐이커 골렘·마티니 스피릿도 디테일 안 깎임 확인.

**교훈**: "안 보인다"는 재현이 안 됐을 때, 같은 카테고리의 다른 원인을 계속 추측하지 말고 **문제가 되는 데이터(여기선 알파 채널)를 직접 시각화해서 눈으로 봐야** 빨리 찾는다. 세 번 추측하고 나서야 이걸 했음 — 다음엔 두 번째 실패 시점에 바로 했어야 함.

EditMode 35 + PlayMode 20 재통과 확인.

### 몹 아이콘 크기 보정 (플레이어에 비해 너무 작아 보임)
투명 처리는 잘 됐지만, 실제 아이콘은 1024px 캔버스 안에 그림 자체가 절반 정도만 차 있어서(여백이 많음) `def.radius` 그대로 스케일하면 체감 크기가 작았음.

**수정**: 스프라이트를 별도 자식 오브젝트("Visual")로 분리 — 루트(콜라이더·물리)는 `def.radius` 그대로 두고, 자식의 스프라이트 렌더링 크기만 `Balance.EnemyIconVisualScale`(2.0배) 만큼 키움. 즉 전투 판정(맞는 범위, 닿는 범위)은 전혀 안 바뀌고 화면에 보이는 그림만 커짐. placeholder(캡슐)는 캔버스를 꽉 채우므로 이 배율 적용 안 함.

EditMode 35 + PlayMode 20 통과 (콜라이더 반지름이 시각 배율과 무관하게 유지되는지도 테스트로 확인).

### 재료 픽업 아이콘도 크기 보정
같은 이유(캔버스 여백)로 재료 드랍 아이콘도 확대. 픽업은 콜라이더 없이 거리 비교로만 동작해서 몹처럼 분리할 필요 없이 `IngredientPickup`의 스케일 계산에 `Balance.IngredientIconVisualScale`(1.6배)을 바로 곱함. 줍는 판정(`CollectDistance`, `PickupRadius`)은 그대로.
