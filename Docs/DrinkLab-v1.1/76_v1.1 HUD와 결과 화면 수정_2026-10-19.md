# v1.1 HUD와 결과 화면 수정

사용자 실제 플레이에서 발견한 두 표시 버그를 수정했다. 이전 MVP 검수에서는 첫 음료 지식 안내와 음료 HUD 조합, 긴 판의 누적 보상을 충분히 확인하지 못했다.

- 안내/학습·카드 선택·일시정지·결과 창에서는 음료 HUD와 재료 알림을 숨기고, 전투로 돌아오면 다시 표시한다. HUD를 모달 뒤로 배치하고 이름·버프·보존 상태에 맞게 높이를 계산한다.
- 결과 화면을 덮던 수백 개의 획득 항목은 재료별로 합산한다. 메인 결과에는 한 줄 요약과 ‘획득 내역’ 버튼을 두고, 상세 스크롤 창에서8종 전체 합계·RP·음료 상태를 읽는다. 실제 창고/정산 데이터는 바꾸지 않는다.
- 작은 창의 상세 창은 본문18px 목표로 자체 크기를 조정하며, 닫기 버튼도 화면 안에 둔다.
- 자연스럽게 띄어 쓴 음료 이름을 실제 HUD에서 확인했다. 기존 자동 이름/예시에는 이미 공백이 있었고, 앞서 표시한 공백 없는 긴 이름은 검사용 고정값이었다. 사용자 레시피 이름을 임의로 바꾸지 않는다.

최종 관련 검사: Edit 대상131/131, 이름 왕복 포함 DrinkGameIntegration19/19, Play 대상38/38 통과. 전체 회귀를 새 소스에 대해 반복한 것은 아니며 관련 HUD·안내·결과·기록·일시정지·키보드 동작과 정산을 검사했다.

실제 QA 실행의 합성 대량 보상(획득 기록226~227건)을 이용해 재료8종의 합산=창고 증가량, RP1회 정산, 결과 버튼의 실제 포인터 판정·획득 내역 열기/닫기, 720/1080/사용자 이미지 크기1622×935/836×705/터치 화면을 확인했다. root가 안내 HUD 숨김·결과/상세 위아래·작은 창18px 본문·정상 띄어쓰기 이름 캡처를 직접 검수했다. 20분을 사람이 직접 플레이한 검사는 아니다.

원래 사용자 이미지의 오른쪽 잘림 자체는 정확히 재현하지 못했다. 동일1622×935 창에서는 HUD와 글자가 화면 안에 있는 것을 확인했다. 획득 ‘기록 건수’와 고정 수량 ‘묶음/추첨 횟수’는 다르다. 한 보상 안의 같은 재료는 원장에 합쳐 기록되므로 실제 추첨은 일반200+정예20+중간3+최종6=229회여도 표시용 원장 항목은226건 등이 될 수 있다. 수량 손실이 아니라 기록 방식의 차이이며 화면 표기는 ‘획득 기록 N건’으로 구분한다.

실행은 [Play-DrinkLab-v1.1-MVP.cmd](Play-DrinkLab-v1.1-MVP.cmd)를 사용한다. 수정 형제 빌드 `Builds/Playable-2026-10-19-drinklab-v1.1-hudfix`와 기존 `Delivery/DrinkLab-v1.1/TestData/drinklab-v1.1` 저장을 연결한다. 기존 재료·RP를 이어 쓰며, 이미 게임이 실행 중이면 새 창을 열지 않고 종료 후 다시 실행하도록 안내한다. 사용자 게임/세이브를 강제 종료·수정하지 않았다.

최종 ZIP의 SHA256은 `704E5B1E22D1FF045D24D2725E47CDB4142A154E146251CDAA0C5968390FB47F`이며 코디네이터가 일치함을 확인했다. 새 폴더에서 격리 실행 30초 생존·Exception 0을 확인했다. 최종 문구 수정은 ‘획득 기록 N건’이며 기존 배치 캡처보다 짧아 추가 캡처는 생략했다. 실행 바로가기를 수정 빌드로 연결했다.
