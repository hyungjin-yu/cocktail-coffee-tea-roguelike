# v1.1 MVP — 보스 재료와 커스텀 음료 제조

사용자 추가 물리/현실성 요구의 구현 기준: [[71_음료 제조 물리와 시각 검증_2026-10-19]]. 얼음 배제 부피·재료 밀도·혼합·액면·붓기 좌표에 대해서는71의 계산/검수 기준을 함께 적용한다.

## 목적과 권한

사용자가 2026-10-19 대화에서 요청한 모든 음료 제조 기획을 보존하고 실제 Unity MVP로 구현한다. 기존 게임에 추가하는 기능이며 기존 카드 성장·직업·무기·도감·기록·저장을 유지한다. 이 문서는 구현 완료 보고가 아니다. 기존 05~11과 충돌하는 음료 제조 항목은 이 문서가 우선한다.

사용자 요구: 보스 전용 제조 재료, 판 종료 시 재료 저장, 출발 전 음료 제조, 한 판 동안의 버프, 5킬 미만 포기 시 음료 보존, 칵테일/차의 실제 재료, 도감과 색·설명 중심 UI, 재료량 직접 입력과 촘촘한 드래그, 지거/다하 계량 모션, 제조·완성 음료 연출, 레시피 저장·재사용·공유, 배합에 따른 색과 투명도, 셰이커 사용 여부를 포함한 기법별 효과 차이.

최신 사용자 수정: 손 위치와 음용 시안의 표현이 어색하므로 손·얼굴·신체가 나오는 연출을 제거한다. 계량·제조는 도구 자체의 움직임으로 보여 주고 마지막에는 완성된 음료만 보여 준다. 마시는 동작은 구현 범위에서 제외하며 이전 음용 필수 조건보다 이 수정이 우선한다.

아래 수치·초기 재료 수·버프 배정·제한은 제작을 진행하기 위한 임시 기본값이다. 대화에서 제안된 모든 예시가 사용자 확정 수치라는 뜻은 아니다. 실제 음료의 건강 효능이 아닌 게임 효과다.

## MVP 범위

실제 게임에서 보스 보상 → 결과 정산 → 창고/재료 도감 → 제조 → 출발 → 버프 적용 → 종료/보존까지 연결한다. 칵테일과 차 모두 지원한다. 커피 제조는 후속이며 기존 커피 성장 시스템은 유지한다.

레시피 공유는 서버 없이 코드 복사/붙여넣기로 구현한다. 온라인 게시판·검색·좋아요는 후속. 정밀 유체/광학 시뮬레이션은 요구하지 않지만 연속 액면·색 혼합·투명/탁함·층 분리와 재료의 형태 차이는 MVP에 포함한다. 정적인 아이콘만으로 계량·제조 모션을 대체하지 않는다.

## 플레이 루프와 저장

1. 중간/최종 보스가 기존 카드용 재료와 별도로 음료 제조 재료를 확정 지급한다. 보스 사망 시 전용 픽업 연출과 런 임시 보상에 기록하며 이동 중 놓치지 않게 한다.
2. 클리어·사망·시간 종료·일반 포기 때 해당 런 획득분을 창고에 한 번만 정산한다. 보스별 획득 ID와 runId로 중복 지급을 막는다. 종료와 저장 실패가 겹쳐도 재시도로 중복되지 않아야 한다.
3. 중간 보스 이후 사망해도 획득 재료는 보존한다. 결과 화면에 획득/창고 반영 여부를 표시한다.
4. 출발 전 레시피 또는 자유 배합으로 제조한다. 제조 확정에서만 재료를 차감하고 준비 음료를 같은 저장 트랜잭션으로 기록한다. 취소·미리보기·레시피 저장은 무료다.
5. MVP는 준비 음료 한 잔/한 슬롯. 준비 음료가 있으면 재제조로 덮어쓰지 않고 그대로 사용한다. 버프 없이 출발할 수 있다.
6. 입장 시 음료 버프를 한 번 적용한다. 카드 선택·일시정지·화면 전환에 소모/중복 적용하지 않으며 런 전체에 유지한다.
7. 전체 유효 몬스터 처치 수 0~4에서 명시적으로 포기하면 준비 음료를 보존한다. 5킬째부터 해당 런에 귀속되어 종료 시 소멸한다. 0~4킬 사망은 보존 대상이 아니다. 보존 포기에서는 그 런의 제조 재료 보상을 정산하지 않는다.
8. 준비 상태·런 ID·처치 수·사용 상태를 저장해 앱 재시작으로 음료를 복제하지 않는다. 강제 종료는 포기 보존으로 취급하지 않는다. 기존 런 복구가 있으면 복구하고, 없으면 비정상 종료로 음료를 소비한다. 제조 후 아직 출발하지 않은 음료는 재시작해도 남는다.

보스 보상 임시값: 중간 보스당 해당 테마 기본 재료 묶음 1회, 최종 보스는 기본 묶음 2회와 희귀 착색 재료 1회. 정확한 재료량/표는 구현 보고서에 남기며 보스 도달 없이도 기능을 배울 수 있게 새 저장에 첫 제조용 세트를 한 번 지급한다. 개발용 반복 지급은 격리 테스트 저장에서만 가능하다.

물과 기본 얼음은 제조 보조 자원으로 무료 제공하고 배합에 기록한다. 차는 찻잎 1종 이상, 칵테일은 베이스 술 1종 이상 필요하다. 종류 전환 시 부적합 재료를 자동 소비하거나 섞지 않는다. 민트·생강·과일 조각·탄산·우유/크림 등은 확장 가능한 데이터 구조로 보존하되 초기 필수 재료 수에는 포함하지 않는다. 탄산 재료를 추가할 때 밀폐 셰이킹을 허용하지 않고 마지막 투입 규칙을 둔다.

도감: 재료 그림, 이름, 실제 색, 맛·향 설명, 사용 가능 음료, 단위, 보유량, 게임 효과, 드랍 획득처. 잠긴 재료는 설명과 획득처를 확인할 수 있으나 소유 없이 사용하지 못한다.

## 계량 UI와 입력

왼쪽 보유 재료/도감, 가운데 도구·재료 계량·잔, 오른쪽 현재 배합·정확한 양·완성 색·기법·버프·소모량 미리보기. 작은 화면은 탭/세로 스크롤로 전환한다. 이름·아이콘·설명을 병기해 색만으로 식별하지 않는다. 실제 플레이 UI에 기술 용어/내부 저장 ID를 노출하지 않는다.

최신 사용자 UI 수정: 상단 ‘음료 제조’는 제목 패널 가운데 정렬하고 좌우 여백을 확보한다. 재료 목록 각 행 오른쪽의 직사각형 색상칸은 제거하며 다른 색상칩으로 대체하지 않는다. 재료는 아이콘·이름·설명으로 구분하고 실제 색은 계량·붓기·혼합·완성 음료에 반영한다. 오른쪽 버프/소모량 영역은 효과와 재료 수에 따라 높이를 계산하고 스크롤하며, 고정 하단 버튼과 겹치거나 목록을 가리지 않는다. HEX/알파 코드 표기는 사용자 화면에서 제외한다.

사용자는 오른쪽 패널의 사용성과 세련된 구성을 추가 요청했다. 배합 → 제조 기법 → 예상 효과의 명확한 위계, 이름/수치가 정렬된 간결한 행, 일관된 기법 선택 버튼을 사용한다. 부가 소모량/재고는 펼치기와 스크롤로 확인하고 하단 제조 버튼은 고정한다. 레시피 저장은 보조 동작으로 구분한다. 큰 단색 사각형 미리보기·반복 안내·내부 계산식·상한 나열은 기본 화면에서 덜어내고 필요한 상세만 별도로 확인한다. 기존 픽셀 분위기를 유지하며 작은 글씨로 압축하는 방식은 사용하지 않는다.

액체 0.1mL, 찻잎 0.1g 단위. 내부 정수 1=0.1단위로 저장해 부동소수 오차를 피한다. 수치 입력과 드래그를 동기화한다. 병/용기를 누르고 드래그하면 기울기와 주입 속도가 바뀌고, 작은 움직임은 느리게 계량한다. 포인터를 놓거나 화면을 나가면 즉시 멈춘다. 키보드 미세 +/- 조절도 제공한다. 소수 입력·음수·NaN·초과 재고·붙여넣기·터치 취소를 검증한다.

임시 한도: 칵테일 액체 합 120mL, 차 물 150mL 고정 + 첨가 액체 최대 30mL, 찻잎 합 0.1~5.0g. 찻잎은 물 용량과 별도로 관리한다. 계량 도구 용량이 넘으면 나눠 붓고 누적량을 표시한다. 슬라이더 눈금이 성기게 점프하지 않아야 하며 표시 수치와 실제 소모량이 일치해야 한다.

확정 전 자유롭게 양을 수정/제거하고 재고는 소비하지 않는다. 실제 계량량이 많을수록 액면/찻잎 더미가 증가한다. 수치상 0.1 변화가 항상 화면의 한 픽셀 변화가 될 필요는 없지만 계산에는 반영한다.

## 버프 계산과 제조 기법

재료량으로 효과가 변하며 실시간 미리보기와 실제 적용은 동일한 계산기를 사용한다. 모든 효과는 수익 체감과 상한을 둔다. 초기 계산: 재료별 정규화 기여 = q/(q+k), 액체 k=15mL, 찻잎 k=2g. 동일 효과 기여를 합한 뒤 기법 배율을 적용하고 효과별 상한으로 제한한다. 물/얼음은 기본 스탯 기여 없음. 버프 표시만 반올림하고 배합량은 그대로 저장한다.

초기 상한: 공격력 +10%, 공격 속도 +8%, 치명타 확률 +5%p, 최대 체력 +10%, 재사용 시간 감소 5%, 이동 속도 +5%. 기여 계수는 한 재료가 무조건 상한을 채우지 않도록 데이터화하고 제작 보고서에 기록한다. 기존 최종 스탯 상한을 초과하지 않으며 임의의 새 전투 시스템을 추가하지 않는다.

구현 연결 결정: 치명타는 기존 히든 스킬의 직접 적중 2배 판정을 재사용하며 음료 확률을 더한다. 재사용 시간 감소는 주무기의 기본 공격 재사용 간격과 기존 보조 활·검 경직·트레이 가시 반격의 대기시간에 적용한다. 공격 속도와 별도 배율이며 기존 최소 간격을 유지한다. 제조 UI 설명에도 적용 대상을 명시한다. 음료를 선택해 출발할 때 사용 기록 저장이 실패하면 제조 화면에 남아 재시도하게 한다. 버프 없이 출발하려면 사용자가 별도로 선택해야 한다.

| 기법 | 제조 모션 | 임시 효과 규칙 |
|---|---|---|
| 셰이킹 | 지거 계량 → 셰이커에 투입 → 흔들기 → 잔에 따르기 | 치명타 기여 ×1.15, 나머지 ×0.95 |
| 스터링 | 계량 → 믹싱 글라스에 투입 → 바스푼 회전 → 따르기 | 공격력/공격 속도 기여 ×1.08, 나머지 ×0.95 |
| 빌드 | 계량 → 마실 잔에 순서대로 붓기 | 전체 ×1.00 |
| 레이어링 | 계량 → 순서대로 천천히 층 쌓기 | 서로 다른 유효 효과 2종 이상이면 전체 ×1.05, 단일이면 ×0.90 |
| 차 우림 | 다하에 계량 → 다관에 찻잎 → 물 붓기 → 우림 → 따르기 | 차 기본 ×1.00 |

기법으로 없는 효과가 생기지 않고 상한은 기법 적용 후에도 유지한다. 차는 우림을 기본으로 하고 온도·시간 미세 조절은 후속이다. 칵테일의 기법별 게임 효과는 현실 제조 원리와 구분한 게임 규칙이다. 반복 제조에서 모션 건너뛰기를 지원하며 결과·소모량은 동일하다.

## 2D 모션과 색

기존 픽셀 스타일과 Aseprite + PixelLab 원본 제작 기준을 유지한다. 도구/병/잔 스프라이트와 마스크·셰이더/동적 채움을 결합한다. 0.1단위마다 개별 프레임을 만들지 않는다.

필수 도구: 지거, 셰이커, 믹싱 글라스, 바스푼, 완성 잔, 다하(茶荷), 다관, 찻잔, 물 용기. 병 기울기·액체 줄기·액면 상승·물결·붓기·찻잎 낙하와 더미·우림 색 변화·증기·완성 음료 공개·버프 획득을 연결한다. 손·얼굴·신체는 표시하지 않고 도구만 움직인다. 셰이킹도 손이 없는 도구 모션이다. 기존 손/음용 시안은 이력으로 보존하되 활성 미리보기와 런타임에서 제외한다. 보존 음료 재입장 때 재제조/재소모하지 않는다.

재료별 기본 색·착색력·흡광/투명도·탁도·점성·층 밀도 데이터를 둔다. 선형 공간에서 양과 착색력을 반영해 혼합하며 단순 sRGB 평균만 사용하지 않는다. 무색 술/물은 희석하고 소량의 강한 색소는 충분히 영향을 준다. 동일 배합은 항상 동일 색이어야 한다. 투명한 진, 푸른 큐라소, 붉은 그레나딘, 탁한 레몬즙이 구분되어야 한다.

셰이킹은 일시적인 기포/탁함, 스터링은 맑은 회전, 빌드는 색 확산, 레이어링은 투입 순서와 밀도에 따른 층 경계를 표현한다. 얼음·반사광은 색 판독을 가리지 않는다. 지거 재료색 → 혼합색 → 완성색을 연결한다. 색은 미관 결과이며 MVP에서 숨겨진 색 점수로 버프를 바꾸지 않는다.

사용자 재확인: 중간 이동에서도 색이 보여야 한다. 병에서 나오는 액체 줄기 → 지거의 해당 재료색 → 지거에서 붓는 줄기 → 열린 셰이커/믹싱 글라스의 현재 누적 혼합색 → 완성 잔으로 따르는 줄기까지 연결한다. 아직 넣지 않은 재료가 중간 혼합색에 미리 반영되면 안 된다. 닫힌 금속 셰이커는 불투명한 외형을 유지하며, 색은 뚜껑을 열어 투입할 때와 밖으로 따르는 액체로 확인한다. 단계별 캡처와 런타임 색 검증을 남긴다.

사용자 추가 규칙: 완성 칵테일과 차 모두 잔을 가득 채우지 않는다. 윗부분에 분명한 여유 공간이 남으며 실제 배합량에 따라 수위가 변한다. 제작 기본값은 서빙 잔 용량 칵테일 150mL, 찻잔 220mL로, 허용 최대 배합에서도 약80~82%만 찬다. 제조 중 도구 용량과 서빙 잔 용량은 구분한다. 완성 공개 화면도 같은 양·색·수위를 유지하며 칵테일은 칵테일 잔, 차는 찻잔을 사용한다. 잔 마스크 전체를 단색으로 채우는 연출은 금지한다. 최소량/최대량의 양쪽 음료 캡처로 검증한다.

사용자 물리 규칙: 빌드/레이어링에서 얼음 추가 시 액면 상승, 제거 시 하강이 보여야 한다. 얼음의 부피·밀도와 잠긴 부피를 반영하고 액체 투입량은 그대로 보존한다. 얼음은 액면에 일부 떠 있으며 색층과 수위가 함께 변한다. 전체 여유 공간은 액체와 얼음 모두 포함해 계산한다. 위150/220mL는 얼음 반영 전 임시 용량이므로, 최종 잔 용량은 허용 최대 액체+얼음에서도 여유 공간을 유지하도록 한 번 확정해 보고서에 기록한다. 같은 배합에서 얼음 수에 따라 잔 크기를 임의 변경하지 않는다. 또는 합계가 초과하면 명확한 용량 안내로 추가를 막으며 재료량을 몰래 줄이지 않는다. 0/1/2/최대 얼음의 액면·층·완성 화면과 액체량 보존을 검증한다. 전체 유체 시뮬레이션까지 요구하지 않지만 얼음을 장식 그림으로만 처리하지 않는다.

## 레시피 저장·재사용·공유

저장: 사용자 이름, 음료 종류, 재료 ID와 정수량/단위, 투입 순서, 기법, 물/얼음, 레시피 스키마 버전. 버프 값은 공유 데이터에서 신뢰하지 않고 현재 밸런스로 재계산한다. 미리보기 색 역시 현재 계산으로 재현한다.

목록에서 선택 → 재료/보유량/버프/색 미리보기 → 제조 확정. 부족한 재료는 도감과 획득처 연결, 자동 대체/자동 차감 금지. 기존 레시피를 복제해 수정할 수 있다. 저장 한도 초기 30개.

공유 코드에는 서버/계정이 필요 없다. 버전·길이 한도·검사값과 입력 검증을 두고 알 수 없는 재료, 허용되지 않는 기법, 중복/음수/초과량, 잘못된 문자, 지원하지 않는 버전을 안내한다. 코드는 명령/파일 경로/실행 코드로 해석하지 않는다. 가져오기는 미리보기 후 저장하며 창고/버프를 즉시 변경하지 않는다. 다른 유저도 자기 재료를 소비한다.

## 구현 소유권과 산출물

- 코디네이터: 본 명세, 결정 기록, 통합 검수, 실행 안내.
- Codex 아트: 신규 ArtSource 하위 원본·PNG·애니메이션/앵커 매니페스트·접촉 시트. Unity C#/.meta 편집 금지.
- Claude 구현: 기존 Unity Assets, 신규 데이터/제조 UI/입력/버프/저장/레시피/공유/임포트/테스트/빌드. 아트 원본 수정 금지.
- 납품: 별도 Windows v1.1 MVP 실행 폴더·ZIP, 격리 저장 테스트 실행 바로가기, 실제 변경/테스트/화면/미해결 보고서. 기존 Android/스토어에 업로드하지 않는다.

## 합격 조건

1. 실제 보스 보상과 종료 저장, 중간 보스 이후 사망 보상, 중복 정산 방지와 저장 실패 재시도.
2. 칵테일/차 재료 필터, 도감 설명·색·획득처와 실제 단위, 없는 재료 제조 거부.
3. 입력/드래그 0.1단위 일치, 경계·취소·터치 해제, 계량·제조·완성 음료 연출과 양에 따른 화면 변화. 손·얼굴·음용 동작이 활성 화면에 없어야 한다.
4. 같은 재료의 양/기법 변경이 미리보기 및 실제 스탯에 동일 반영, 일시정지·재시작 중복 적용 없음.
5. 0킬/4킬 포기 보존, 5킬 포기 소모, 조기 사망 소모, 보존 재입장, 제조 후 재시작 유지, 강제 종료 복제 방지.
6. 레시피 저장/수정/재사용/복사/다른 저장에 가져오기와 동일 배합·색·효과 재현, 잘못된 코드 거부.
7. 무색 희석·강한 착색·탁도·셰이킹/스터링/층 분리 화면 비교. 원본/ready/integrated/verified 상태 구분.
8. 기존 저장 마이그레이션과 손상/실패 복구, 실제 사용자 세이브 보존. 기존 전투/카드/기록 회귀.
9. Windows 실행본과 ZIP 새 폴더 실행, 1280×720/1920×1080 및 터치 UI 배치 검수. 완료 증거는 새 실행 결과만 사용한다.

## 후속 확장으로 보존할 기획

커피 제조, 재료/레시피 종류 확대, 우림 온도·시간 조절, 셰이킹 강도·시간 조절, 탄산 후첨/가니시/크림, 다양한 잔과 얼음, 고급 층 경계, 온라인 커뮤니티·추천·검색. 이는 현재 요청의 핵심 계량/색/기법/코드 공유를 빼기 위한 대체 범위가 아니다.
