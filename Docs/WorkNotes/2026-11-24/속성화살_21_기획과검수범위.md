# #21 속성 화살 (화상·빙결·감전·중독) — 기획, 구현, 검수 범위

작성일: 2026-11-24 · 브랜치 `hyungjin-yu/elemental-arrows`.
Unity와 빌드를 쓰지 않은 상태에서 C# 4개 어셈블리(Runtime, Editor, EditMode, PlayMode)와 `CCT_PLAY_VERIFIER` 변형을 Unity 6000.3.25f1에 들어 있는 Roslyn으로 컴파일만 확인했다. 컴파일 오류는 0건이다. 테스트는 아직 실행하지 않았다.

## 1. 추적 결과 (기존 인프라)

- **기본 활**: `WeaponKind.Bow`. 티 소믈리에의 시작 무기이며 `PlayerProjectileWeapon`을 총과 함께 쓴다. 기본 관통은 1이다.
- **보조 활(티니 보우)**: 바텐더가 레이피어로 시작하고 조건을 채우면 붙는 `HybridBowWeapon`이다. `tea_arrow`를 주인 없이(`owner=null`, `original=false`) 쏘므로 상태이상이 붙는 경로가 없다.
- **기존 화상/떫은 여운**: 칵테일·차 카드로 얻는 `FlameLevel`/`PoisonLevel`이다. 모든 무기의 원래 타격에 붙는다(`EnemyHitStatus`). 새 속성 화살은 이것과 **별개 상태**(`ArrowElementStatus`)로 두었고, 서로 덮어쓰지 않는다.
- **보스 저항**: `Enemy.TryStagger`와 `ApplyDrinkSlow`는 보스를 이미 제외한다. 빙결은 이 경직 면역을 그대로 쓰고, 보스에는 별도 대체 규칙을 둔다.
- **레벨업 풀**: `CardSystem.Draw(category, isRanged…)`이다. 찻집(직업 테마 모드)에서는 칵테일 카드 창이 열리지 않으므로 새 카드는 **차 카테고리**로 넣었다.
- **카드 DB**: `Resources/Cards` 에셋 35장(07 §3 기본 34장 + 하이브리드)이다. 속성 화살 4장은 에셋으로 굽지 않았다. 코드에서 정의하고 `CardDatabase.LoadAll()`이 목록 뒤에 덧붙인다. 그래서 기존 07 표 검사와 에셋/기본값 일치 검사는 그대로 유지된다.
- **적과 발사체**: 둘 다 풀에서 재사용하지 않고 `Destroy`한다. 그래서 상태는 적과 함께 사라진다.
- **세이브**: 런 중간 저장은 없다. 런 기록과 도감은 카드 id 문자열로 저장되며, 새 카드 id도 `LoadAll`에서 이름으로 찾아진다. `CardEffectType`과 `WeaponRestriction` enum은 **끝에만** 값을 추가했으므로 기존 정수 값이 바뀌지 않는다.

## 2. 적용 범위

| 무기/경로 | 속성 화살 카드 등장 | 속성 적용 |
| --- | --- | --- |
| 기본 활(시작 무기) 원래 화살 | O (차 카드 창, `BowOnly`) | O |
| 총 | X | X (같은 무기 컴포넌트지만 `isBow=false`) |
| 레이피어/검 | X | X |
| 보조 활(티니 보우) | X | X (주인 없는 비원본 화살) |
| 관통 최종 형태 파편, 확산 최종 형태 옆 화살 | — | X (비원본) |

혼합 무기나 보조 활로 자동 전파하지 않는다. 보조 활에 쓸 `tea_arrow` 변형 아트는 ArtSource에만 보존해 두었고 런타임에는 넣지 않았다.

## 3. 규칙 (`ArrowElementRules`, 카드 문구도 이 상수로 만든다)

카드 4장 모두 차 카테고리, 희귀 등급, 최대 3중첩(= Lv 3)이다.

| 속성 | 발동 | 행동 | Lv1 / Lv2 / Lv3 | 상한과 중첩 |
| --- | --- | --- | --- | --- |
| 화상 | 원래 화살이 적중 | 2초 동안 초당 4번 피해 | 초당 공격력의 30 / 40 / 50% | 다시 맞히면 2초로 갱신, 더 센 값 하나만 유지, 겹치지 않음 |
| 빙결 | 원래 화살이 적중 | 일반 적: 1초 동안 이동과 몸통 공격 정지(기존 경직). 보스: 정지하지 않음 | 같은 적 재빙결 대기 4 / 3 / 2초. 보스는 이 화살 피해 +10 / 20 / 30% | 기존 경직 쿨다운을 같이 쓴다(모카 경직 포함). 무한 정지가 생기지 않는다 |
| 감전 | 이 화살의 **첫** 대상 | 250cm 안에서 가장 가까운 다른 적으로 연쇄 | 1 / 2 / 3마리, 화살 피해의 40% | 관통해도 연쇄 횟수가 늘지 않는다. 연쇄 피해는 보조 피해라 상태, 히든, 재연쇄가 없다. 같은 적은 0.25초 동안 연쇄를 다시 받지 않는다 |
| 중독 | 원래 화살이 적중 | 6초 동안 1초마다 피해, 맞힐 때마다 1중첩 | 중첩당 초당 공격력의 5 / 7 / 9% | 최대 5중첩. 맞히면 6초로 갱신 |

- **순환(사용자 확정)**: 화상 → 빙결 → 감전 → 중독 → 화상 순서로 돈다. 얻은 속성만 돌고, 얻지 않은 속성은 건너뛴다. 원래 화살이 **실제로 한 발 나갈 때마다** 한 칸을 쓴다. 대상이 없어 쏘지 않으면 칸을 쓰지 않는다. 다중 발사에서는 실제 spawn 순서대로 칸을 쓴다. 같은 카드를 다시 고르면 레벨만 오르고 순서 칸은 그대로다. 런이 끝나면 새 `PlayerStats`로 초기화된다.
- **같은 발사 묶음 중복 제한**: 다중 발사 한 번에서 같은 속성은 같은 적에게 한 번만 발동한다. 화살 피해 자체는 매 화살 들어간다. 서로 다른 속성은 각자의 상한 안에서 따로 발동한다.
- **머리 위 미리보기**(`ArrowQueuePreview`): 머리 위에 위를 향한 정지 화살 그림(`*_arrow_low`)을 한 줄로 보여 준다. 왼쪽부터 쏘는 순서다. 다음 발사 묶음(1 + 다중 발사, 최대 8발)은 크고 진하게, 그 뒤 3발은 작고 흐리게 그리며 묶음 사이에 간격을 둔다. 착탄 순서가 아니라 **발사 순서**다. `PeekArrowElement(i)`는 실제 소비와 같은 계산을 쓴다. 속성이 없으면 숨긴다. 표시할 아이콘 수에 상한이 있어 너비가 약 1.6월드를 넘지 않는다.
- **다른 시스템과의 관계**
  - 직업 깊은 우림: 차 카테고리라 같은 차 추가 중첩으로 계산된다.
  - 혼합 러시: 바텐더 전용이라 무관하다.
  - 히든 스킬 불꽃 쇼와 겹치는 여운: 기존 화염/여운 상태만 보므로 속성 화살과는 연동되지 않는다.
  - 진상 손님 봉인: `FlameLocked`/`PoisonLocked`는 카드 화염과 여운만 잠그고 속성 화살은 잠그지 않는다. 기획 확인이 필요하다.

## 4. 아트 연결 (Codex 납품 a059d5b, `ArtSource/elemental-arrows-2026-11-24` 반입)

런타임 경로는 `Resources/ArtExtra/arrow_element/<속성>_<클립>/<속성>_<클립>_NN.png`이다. 임포트 규칙은 `IconImportSettings`에 있다(128 PPU, 점 필터, 무압축, 연쇄 클립은 피벗 (0.0625, 0.5), 나머지는 가운데 피벗).

| 클립 | 쓰는 곳 | 보통 | 저이펙트 |
| --- | --- | --- | --- |
| `arrow` / `arrow_low` | 비행 화살 그림(기존 화살과 같은 배율·회전), 머리 위 미리보기 | 3프레임 루프 85/95/105ms | `arrow_low` 정지 |
| `hit` / `mark` | 명중 지점 | 4프레임 원샷 240ms | `mark` 0.15초 정지 |
| `active` / `mark` | 머리 위 상태 표식(화상, 빙결 중, 감전 0.4초, 중독은 중첩만큼 조금씩 커짐) | 4프레임 루프 650ms | `mark` 정지(상태는 항상 보임) |
| `shock_chain` / `chain_low` | 두 적 사이 연쇄(시작 앵커에서 끝 앵커까지 112px를 거리에 맞춰 X 방향으로 늘림) | 4프레임 원샷 210ms | `chain_low` 70ms |

아트가 없으면 속성 색 틴트, 원, 선으로 대체한다. 속성 화살에는 기존 화염/여운 꼬리 대신 속성 아트를 보여 준다.

## 5. 다른 변경과 겹치는 범위 (통합할 때 주의)

- `CardSystem.Draw`, `IsWeaponCompatible`: 선택 인자 `isBow`가 추가됐다. 기본값이 false라 기존 호출과 동작이 같다.
- `CardDatabase.LoadAll`: 속성 화살 4장을 덧붙인다. 카드 수를 세는 테스트 4곳을 수정했다(Spec07, GrowthSpec, PlayFeedback1122 색표, FirstPassArt 도감 행 수 35 → 39).
- `PlayerProjectile.Spawn`: 선택 인자 `element`, `volley`가 추가됐다. `PlayerProjectileWeapon.Fire`와 `PlayerStats`도 바뀌었다.
- `CardEducationData` / `Summary`: 출처는 기존 카드가 이미 쓰는 URL만 다시 인용했다. 문장 표현은 편집 검토가 필요하다.
- 도감 차 열이 18장에서 22장으로 늘어난다. 바텐더 플레이어에게는 얻을 수 없는 카드로 보인다.

## 6. Unity 후속 검수 범위 (지금은 실행하지 않음)

1. Unity가 새 PNG, 폴더, `.cs`의 `.meta`를 생성하는지 확인하고 커밋한다. 임포트 설정(피벗, PPU, 점 필터)이 맞게 들어갔는지 본다.
2. EditMode 테스트: `ArrowElementTests` 신규, 수정한 4개 테스트, `IntegerOnlyTests`, `CardEducationTests`, `FeedbackBatch1`(효과 2줄 맞춤).
   - 참고: 기존 검 설명의 "0.25초"는 이번 변경 전부터 소수 금지 검사에 걸릴 수 있다.
3. PlayMode 테스트 `ArrowElementPlayTests` 13개 항목:
   - 실제 활과 총
   - 다중 발사 spawn 순서와 미리보기 일치
   - 보조 활과 비원본 화살 제외
   - 화상, 중독 상한, 빙결 일반 적/보스, 감전 연쇄 범위와 관통
   - 적 사망, 주인 사망, 저이펙트, 같은 발사 중복 제한, 속성 없을 때 숨김
4. 실제 화면에서 확인할 것:
   - 비행 화살의 회전과 크기
   - 명중 위치, 머리 위 상태 표식이 카드 화염/여운 표식이나 보스 체력바와 겹치지 않는지
   - 미리보기가 HUD와 경고를 가리지 않는지(720p, 1080p, 4:3, 다중 발사 8발)
   - 저이펙트 화면
5. 두 직업과 두 모드(일반, 직업 테마)에서 카드 창을 확인한다.
   - 티 소믈리에 + 활: 등장
   - 티 소믈리에 + 검, 바텐더 + 총, 바텐더 + 레이피어 + 티니 보우: 등장하지 않음
6. 균형 측정:
   - 감전 Lv3 + 다중 발사 8발 + 관통 6 조합의 처치 속도
   - 중독 5중첩의 보스 피해
   - 화상은 정수 피해 반올림 때문에 Lv1에서 실제로 약 11% 더 강하게 나온다

## 7. 남은 아트 요청 (선택)

- 카드 교육 아이콘 4종(`CardEducation/card_arrow_*`, 64×64). 지금은 차 카테고리 아이콘으로 대체되어 있다.
- 보조 활에도 속성을 넓히기로 결정할 경우에만 `tea_arrow` 변형을 연결한다(이미 납품됨).
