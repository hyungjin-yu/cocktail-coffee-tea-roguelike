# 작업 상태와 사용자 환경 보호

이 규칙은 코디네이터와 작업자 모두에게 적용한다.

- 워커에게 메시지를 보낸 성공 응답은 전달 증거일 뿐 실행 증거가 아니다. 이 상태는 사용자에게 '전달했다'고만 보고한다.
- '작업 중'이라고 보고하려면 해당 응답 시점에 worker-show의 liveness=live/activity=working과 최근 worker-read의 실제 작업 기록을 함께 확인한다. 오래된 기록, ready, input_accepted만으로 진행 중이라고 말하지 않는다. 증거가 없으면 미확인 또는 대기라고 명시한다.
- 종료/오류/사용량 제한 알림을 받으면 실제 상태를 확인하고 같은 Task에서 공식 복구 절차를 따른다. 메시지를 보내는 것만으로 복구됐다고 말하지 않는다. 중복 워커나 중복 Unity 시험을 만들지 않는다.
- 완료는 변경 파일·실제 검사 결과·미검증 항목을 대조한 뒤 판정한다. 컴파일, 자동 시험, fixture 화면, 사람 플레이를 구분한다.
- 사용자 게임 중에는 게임 프로세스, 창, 입력, 포커스, 해상도, 음량을 조작하지 않는다. 소리를 내거나 성능을 방해하는 검수·빌드는 보류하고 독립 작업을 진행한다.
- 시각 마감/PC 종료를 맡았을 때 지시 전달만으로 자동 실행을 보장하지 않는다. 실제 예약/실행 장치, 시각, 저장 순서, 결과 확인 수단을 확보한 경우에만 보장한다. 확보하지 못하면 즉시 한계를 알린다.
- 컴퓨터 종료는 사용자 지시의 선행조건(작업 중단, 소스·로그·재개 기록 저장)을 실제 확인한 뒤 실행한다. 강제 종료나 종료 시각 변경은 임의로 하지 않는다. 과거 특정 날짜 종료 지시는 다음 날 재개에 재사용하지 않는다.
- 현재 재개 작업(2026-11-16)은 컴퓨터 종료 금지. 사용자가 던파 종료와 진행을 명시했으므로 메모리·에디터 게이트 확인 후 Unity 시험·빌드·화면 검수를 재개할 수 있다. 사용자 입력·실제 저장 보호와 무음 작업은 유지한다.
- 상태 보고용 반복 호출은 줄이되, 실행 증거를 생략하지 않는다. 결정·차단·검증 결과를 중심으로 짧게 보고한다.
