# 협동 실험판 전용 맵 개선

사용자 피드백: '화면 크기며 몹이 주방 밖으로도 나오는거며, 배경 타일이며' 변경할 점이 많다. 코디네이터가 화면·역할공간·적 이동경계·배경/충돌을 맞춘 전용맵 한 장을 제안했고 사용자가 '진행해'로 실행 승인했다.

## 이번 기본안

**최신 사용자 확정 방향:** '기존 화면에 주방 영역을 추가해서 더 커지는 느낌으로 가야지.' 기존 홀의 전투 면적·캐릭터/적/배경 타일의 체감 크기를 보존하고, 외곽에 별도 주방 공간을 증축해 월드 면적을 확장한다. 기존 홀 안을 나눠 주방을 끼워 넣거나 전체 확장 맵을 기존 화면에 억지로 맞춰 축소하지 않는다. 아래 '한 화면'·'위/아래 분할'은 초기 제안으로 이 방향보다 우선하지 않는다. 증축 방향은 기존 맵·동선 기준으로 최소안을 제시하며, 개별 카메라 표시방식/2분할은 미확정이므로 자동 확정하지 않는다. 확장으로 두 플레이어가 공유 화면에서 동시에 보이지 않는 문제는 숨기거나 강제이동/강제줌으로 덮지 말고 카메라 대안과 함께 보고한다.

- 11-17 final 실험판과 싱글판/저장/공개패키지는 보존한다. 새 11-18 별도 검수본으로 제공한다.
- 한 화면의 고정 카페 맵. 위쪽 주방(제조)과 아래쪽 홀(전투)을 바 카운터/패스카운터/명확한 출입구로 구분한다. 2명 모두 현재 위치·역할·전달 위치를 읽을 수 있게 한다.
- **주방은 안전한 제조 구역, 적은 홀에서만 이동**하는 것으로 이번 기본안을 정한다. 기존 '홀이 비면 몬스터가 주방까지 쫓아감'을 제거한다. 이 안전구역 해석은 원래 발언이 상세 규칙까지 지정한 것이 아닌 구현 기본값임을 결과에 명시한다.
- 적 스폰·추격·밀쳐내기·분리·충돌·경계 조건에 같은 홀 제한을 적용한다. 플레이어는 지정 출입구로만 오가고, 주방 안 플레이어는 적의 공격 대상에서 제외한다. 주방에서 벽 너머 자동 공격으로 안전 파밍 불가.
- 둘 다 주방에 있을 때는 적이 홀에 남아 압박을 쌓되 적 수는 상한을 유지한다. 이 시제품의 체험 목적은 두 역할의 협력이고, 적 위험을 무조건 없애거나 자동 승리를 정상 진행처럼 숨기지 않는다. 승패 조건까지 재설계가 필요하면 구현 전 구체안 보고.
- 안전구역 대기만으로 승리하는 허점을 막는 최소 기본값: 5분 목표는 '전투 진행 시간'으로 표시하고 살아 있는 플레이어가 1명 이상 홀에 있을 때만 누적한다. 둘 다 주방/쓰러짐 상태면 목표와 난이도 진행을 멈추되 제조·전달·회복·부활 및 홀의 적 움직임은 정상 동작한다. 전체 일시정지와는 구분한다. 이 변경과 표시를 검사하며 불필요한 강제퇴장/주방피해/새패널티를 만들지 않는다.
- 문 가장자리/코너에서 플레이어가 끼이거나 두 사람이 상대를 막지 않게 한다. 경계 한 줄로 역할이 흔들리는 문제 없이 역할 전환 위치를 그림과 일치시킨다.
- 화면 크기 피드백은 단순 창 크기만이 아닌 게임판·캐릭터·작업대·HUD의 상대 크기 문제로 다룬다. 720p/1080p/4:3에서 중요 공간·HUD·바닥이 잘리지 않게 카메라 framing을 계산하고, 넓은 화면은 맵을 과도하게 확대하거나 끝없이 타일을 늘리지 않는다. 16:9 기본에서 캐릭터/잔/적/도구 판독을 우선한다.
- 장식 배경과 플레이 바닥을 분리한다. 카페 배경을 바닥 전체에 잘못 반복하거나 테두리를 늘려 무늬 크기가 어긋나는 표현을 제거한다. 실제 승인 타일/스프라이트를 확인해 주방 바닥과 홀 바닥·벽·카운터·입구·적 진입점을 구성한다. 동일한 크기/픽셀밀도를 유지하며 그림상 통로와 충돌이 일치한다.
- 작업대는 플레이어·완성잔·진행표시와 겹치지 않게 위치/깊이를 맞춘다. 카운터 수령 위치와 조작 안내는 두 사람이 근처에 있을 때도 분리해 읽힌다. 접근 가능한 앞면을 명확히 한다.
- 기존 3재료/3음료/2인입력/교대/공유재고/부활/Pause는 유지하고 온라인·새경제·직업확장은 하지 않는다. 재료·스킨 확대는 범위 밖.

## 아트와 소유권

## 추가 사용자 지시: 플레이어별 카메라

**최신 정정:** 사용자가 '꼭 2분할 해야해?'라고 반문했다. 아래 2분할은 코디네이터가 먼저 선택한 안이며 사용자 확정 사항이 아니다. 분할 전용 구현은 보류한다. 기존 공유 화면을 유지하고 독립적인 맵/적 경계/화면 framing 개선은 계속한다. 플레이어별 카메라 구조와 실제 화면 표시 방식은 구분하며 아래 분할 명세는 대안 검토 기록으로만 둔다.

사용자가 '플레이어마다 카메라를 배정하는 것도 좋을 것 같은데'라고 제안했다. 위 한 화면 기본안의 카메라 부분을 수정하여 플레이어별 추적 카메라 2개·로컬 분할 화면을 이번 개선에 포함한다. 같은 월드·실제 캐릭터를 렌더링하며 월드/재고/적을 복제하지 않는다.

- 16:9에서는 좌우 분할을 기본으로 하고, 각 뷰의 화면비로 카메라 framing을 계산한다. 4:3은 상하 분할 등 실제 가독성이 나은 배치를 검증해 선택하고 README에 명시한다. 불필요한 동적 합침/갈라짐 연출은 이번 범위가 아니다.
- P1/P2 색·이름·화면 경계를 분명히 한다. 각 뷰는 해당 플레이어 위치를 추적하되 맵 밖 빈 공간 노출/경계 튐/벽 안 보임을 막는다. 주방·홀 이동이나 역할 교대가 카메라 또는 입력 소유권 교대를 의미하지 않는다.
- 플레이어 체력/역할/소지잔/효과/제조 진행과 상호작용 안내는 본인 뷰에 맞춰 표시한다. 공유 재고·전투 진행 시간·Pause/결과는 화면 공통 영역으로 두고 두 번 복제하지 않는다.
- 월드→HUD 좌표 변환은 플레이어별 camera.pixelRect 기준으로 처리한다. 작업대/카운터/쓰러짐 안내가 반대편 화면에 뜨거나 분할선에 잘리지 않아야 한다. HUD/카메라/입력 구분과 Pause/재시작 후 카메라 중복 생성 방지를 검사한다.
- 가능하면 기존 공유 화면을 비교용 설정으로 보존하되 필수 합격은 새 2분할 경로다. 무리한 UI/설정 확장은 하지 않는다.
- 720p/1080p/4:3에서 두 명 주방·두 명 홀·각1명·경계 교차·카운터 전달·부활·Pause/결과 캡처 및 실제 분리 입력 검증. 사람 직접 협동 체감은 미실시로 구분한다.

기존 승인 아트 재배치가 우선이다. 바닥/경계/문 등의 실제 자산이 부족하면 임시 도형을 최종 아트로 처리하지 말고 필요한 asset ID·캔버스·배치도·참조를 보고한다. 새 그림은 Codex가 Aseprite+PixelLab으로 제작, Claude는 코드·Unity 임포트·검수·빌드 담당. 새 원본을 Claude가 그려 넣지 않는다.
