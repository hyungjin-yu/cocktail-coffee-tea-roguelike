# 싱글 카페 입장형 첫 화면

## 사용자 요청과 적용 대상

게임 실행 시 버튼만 모인 심심한 첫 화면을 개선한다. 카페 문을 열고 들어가는 애니메이션 뒤에 실제 카페 내부가 나오고, 각 버튼은 이름·목적에 맞는 내부 위치에 있다. 사용자 추가 답: **기존 싱글판부터 적용**. 협동 Prototype은 변경하지 않는다.

기존 타이틀 메뉴의 시작·영구 강화·도감·설정·제작 정보·종료·스킨·최근 기록·저장 오류/임시 플레이/재시도 기능을 보존한다. 기존 중앙 세로 버튼 배치는 교체하되 상점·저장·진입 규칙을 바꾸지 않는다. 시작은 기존 직업/무기/제조 흐름에 연결하고 버튼 하나 때문에 새 기본 플레이 모드를 만들지 않는다.

## 최상위 사용자 기준: 현실성

**최신 톤 지시와 플레이 피드백:** 사용자는 카페 첫 화면과 실제 게임의 톤이 전혀 다르므로 한쪽으로 맞추라고 했고, 이어 '칵테일 바 게임 배경이 너무 어두워 불편하다는 피드백'을 전달했다. 따라서 코디네이터의 잠정 '어두운 전투 톤에 타이틀 맞춤'은 철회한다. **칵테일 바 전투 가독성을 먼저 밝게 보정하고, 첫 카페 화면을 같은 따뜻한 목재·조명·색/픽셀 밀도에 맞추는 방향**이다. 주방/찻집/협동을 무관하게 전부 색보정하지 않는다.

- 야간 바 정체성은 유지하되 바닥/벽/기둥·적/플레이어/드롭·투사체가 암부에서 묻히지 않게 한다. 재질의 중간 명도와 실제 조명, 과도한 검은 오버레이/비네트/틴트 유무를 먼저 조사한다. 밝기 수치만 임의상승시켜 끝내지 않는다.
- 화면 전체에 흰 반투명판을 덮어 글자/스프라이트/색을 씻어내는 처리 금지. 배경만 밝힌다고 적탄 대비가 오히려 떨어지지 않는지 정상/군중/보스/드롭/저이펙트 화면과 흑백 미리보기 비교.
- 첫 실내의 회색/평평한 재질과 전투 바의 진한 픽셀 재질이 다른 문제를 함께 해결한다. 같은 참조 팔레트/목재·벽·바닥과 조명색을 공유하되 기능별 시야 차이(메뉴 가독성/전투 가독성)는 허용한다. 글자/핫스팟 현실성과 외부→내부 조명 연속성도 유지.
- 조정 전후 같은 상태·해상도 캡처와 수정한 색/렌더값 또는 아트 ID를 기록한다. 실제 모니터 체감은 별도 사람검수이며 자동검사 통과만으로 불편 해소 확정하지 않는다.
- 전투 수정은 기존 싱글 칵테일 바 배경 표현에 한정하며 적 스탯/스폰/피해·판정·저장 규칙은 변경하지 않는다. 기존 검수본/아트 원본·새 팔레트/보정본을 구분 보존한다. 아트 수정이 필요하면 Codex, Unity 렌더/임포트는 Claude 소유권 준수.

추가 사용자 지시: **'가장 중요한건 현실성이 있는가야.'** 기존 픽셀 아트 스타일을 유지하되 실제 있을 법한 카페의 공간·동작·사물 관계가 성립하는 것을 기능 수·장식·연출 화려함보다 우선한다. 실사 스타일로 바꾸라는 지시가 아니다.

- 레이아웃부터 실제 카페 평면도를 생각한다. 입구→손님 통로→주문/픽업 카운터, 카운터 뒤 제조 공간, 벽 책장·게시판, 직원의 연구 테이블·옷걸이 위치가 접근성과 용도에 맞아야 한다. 클릭 지점 8개를 균등 배치하려고 방 구조를 왜곡하지 않는다. 손님/직원 동선을 구분하고 가구가 출입문·이동 공간을 막지 않는다.
- 한 시점·바닥 기준선·가구 비례·원근·광원 방향을 일치시킨다. 컵과 라디오가 사람만큼 커지거나, 노트북이 공중에 뜨거나, 물체를 얹을 면 없이 벽에 붙어 보이지 않게 한다. 장식물은 표면에 접지하고 가구 뒤/앞 가림 순서를 맞춘다.
- 문틀/문짝/손잡이/경첩은 실제 개폐가 가능한 관계여야 한다. 문은 경첩에서 회전하고 벽을 통과하지 않으며, 문턱·진입 방향·실내에 보이는 출입문 위치가 일치한다. 카메라가 벽/가구를 통과하거나 외부와 내부의 문 위치가 바뀌지 않는다. 2D 픽셀에서 문 회전 표현이 부족하면 의미 없는 그림 늘이기로 대체하지 말고 정면 개폐 프레임/일관된 이동 경로를 제작한다.
- 문 밖에서 내부가 미리 보이면 최종 내부와 같은 가구/조명 관계를 유지한다. 문짝·문틀·깊이 레이어를 사용해 '문을 통과함'이 읽히게 하고 단순 줌/어둠페이드만으로 입장 완료를 주장하지 않는다.
- 메뉴 기능과 사물의 연결도 납득돼야 한다. 실제 출력 조절을 떠올리는 라디오=설정, 책장=도감, 장부=최근 영업기록, 옷장=스킨, 노트북=성장 관리. 시작은 카운터에서 영업 준비를 시작하는 동작으로 읽히게 한다. 목적 설명이 실제 연결되는 메뉴 범위를 과장하지 않는다.
- 상호작용 가능한 물체에는 세계에 어울리는 작은 이름표/명패를 쓰고, hover/focus는 절제된 테두리/작은 안내로 충분하다. 가구마다 거대한 버튼·네온 빛/입자·공중 카드가 생겨 공간을 덮지 않게 한다. UI 오류·접근성·저장 안전 안내는 읽을 수 있는 별도 계층을 유지한다.
- 구현 전에 평면도+카메라 시점+가구/문 스케일·입장 경로 도식을 공유하고, 아트와 구현이 같은 좌표계를 쓴다. 실제 연속 프레임에서 문 접합/문턱/가림·동선·조명 일관성을 검수한다. 수치/스크린샷 한 장 통과만으로 현실성 완료 판정하지 않는다.

## 첫 경험

**최신 사용자 추가:** 게임 최초 화면은 자동 입장이 아니라 **간판과 문이 보이는 외관 대기**다. 간판에 게임명, 문 근처에 `입장하기`와 보조 안내 `아무 키나 눌러 입장`을 표시한다. 클릭 가능한 입장 동작 또는 새 키 입력으로만 문 개폐→문턱→실내 연출을 시작한다. 입력 전에는 시간이 지나도 문이 저절로 열리거나 내부로 넘어가지 않는다.

- 상태를 ExteriorWaiting → Entering → Interior로 분리한다. 로딩/창 포커스 전환/직전 실행 키가 입장으로 새지 않도록 입력 수신 준비 시점과 신규 press를 구분한다. `입장하기`는 접근성 키보드/클릭/터치 모두 지원한다.
- 첫 입력은 입장 시작에만 소비하며 같은 입력으로 스킵/시작/종료를 실행하지 않는다. 누른 키를 유지해도 중복 입장 없음. 입장 중 별도의 새 입력으로 건너뛰기는 가능하되 완료 후 첫 메뉴 프레임까지 click-through 방지.
- 일반 메뉴 복귀 때는 실내를 유지하고 외관 입장 대기로 되돌리지 않는다. 저이펙트에서도 외관 대기·명시 입력은 유지하고 입장 동작만 간소화한다. QA replay/reset도 대기와 자동재생 경로를 명확히 구분한다.
- 720/1080/4:3에서 간판명·문·입장 문구 겹침/가림 없음, 무입력 대기·키/클릭 진입·키 유지·별도 스킵·재진입·포커스 전환을 실제 빌드에서 검증한다.

1. 짧은 외부/문 전경에서 카페의 간판과 문을 인식한다.
2. 문짝이 경첩을 중심으로 열리고 문 안의 따뜻한 빛이 드러난다. 카메라가 문턱을 넘어 실내로 이동한다. 단순 어둠 페이드나 소품 등장만으로 '문 열고 들어감'을 대신하지 않는다.
3. 같은 카페의 실내 구도에 자연스럽게 도착한다. 장소마다 클릭 가능한 오브젝트와 짧은 한글 이름표가 있다. 배경은 장식 그림 뒤 임의 좌표의 카드나 중앙 버튼 더미가 아니라 기능이 있는 공간으로 읽힌다.
4. 연출은 대략 2~3초의 짧은 목표이며 클릭/키 입력으로 건너뛸 수 있다. 건너뛴 입력이 바로 시작/종료를 눌러버리지 않게 한 프레임 입력 소비를 구분한다. 실내 메뉴 진입 후 중복 오버레이가 남지 않는다.
5. 메뉴에서 돌아올 때 문 입장을 반복 강제하지 않는다. 저이펙트는 흔들림/강한 점멸/과한 확대 대신 짧고 안정된 전환. 게임 창 비활성/해상도 변경/느린 프레임에서도 완료 상태가 정상이다. 무음 검수, 새 사운드 생성 불필요.

## 장소와 기능 매핑(이번 구현 기본안)

**최신 사용자 수정:** 게임 이름이 매장 외부 간판에서 보여야 한다. 기존 GameInfo.Title의 실제 이름을 간판 표면에 읽히게 합성하며 UI 제목을 위에 띄우는 것만으로 대체하지 않는다(한글은 Unity 텍스트, 간판 원근/명암과 정렬). 노트북은 독립 연구 테이블 대신 **바 카운터 맨 왼쪽 또는 맨 오른쪽 끝**에 둔다. 자연스러운 동선·다른 물체 가림·기능 분리·작은 화면 판독에 유리한 끝을 담당자가 선정하고 이유를 보고한다. 표의 노트북 행은 이 최신 수정이 우선한다. 평면도/양방향 입장뷰/실내 레이어/노트북 hotspot·label·navigation을 같은 위치로 갱신한다. 4:3 contain에서도 간판 글씨와 카운터 끝 노트북을 잘라내지 않는다. 구버전 아트 manifest는 보존하고 최신 해시로 재발행·반입한다.

| 장소 | 이름표 | 연결 |
|---|---|---|
| 영업 준비가 보이는 카운터/작업대 | 시작 | 기존 RequestStart → 직업/무기/제조 |
| 노트북이 놓인 연구 테이블 | 영구 강화 | 기존 PermanentSkillView |
| 레시피·재료 책이 있는 책장 | 도감 | 기존 CardCodexView |
| 옷걸이/의상 진열장 | 스킨 | 기존 SkinShopView |
| 영업 장부/영수증 묶음 | 최근 기록 | 기존 RunHistoryListView |
| 라디오/조절장치 | 설정 | 기존 SettingsView |
| 제작자 메모/직원 게시판 | 제작 정보 | 기존 CreditsView |
| 실내의 출입문 | 종료 | 기존 저장 실패 안내·확인 포함 RequestQuit |

- 시작 지점은 첫눈에 알아보도록 가장 분명한 조명/공간적 중심을 준다. 종료는 입장 스킵과 같은 위치의 무심코 클릭으로 즉시 종료되지 않게 한다.
- 라벨은 Unity 텍스트로 유지하고 아트에 굽지 않는다. 이름표는 각 물체 옆/아래에 작고 명확히, 물체를 덮는 큰 직사각 버튼 나열 금지. Hover/focus 시 외곽선·은은한 빛·짧은 목적 설명. 터치에는 hover 의존 없이 이름표가 보인다.
- 클릭 영역은 오브젝트를 충분히 포함하지만 이웃 기능을 침범하지 않는다. keyboard Tab/방향키·Enter/Esc 선택과 포커스 강조를 유지하고 논리적인 이동 순서를 정의한다. 평소 강제 파란 선택 테두리는 재도입하지 않는다.
- 제목은 카페 간판/상단 안전 영역에 간결하게. 긴 설명·개발용 MVP 표시는 주시선을 점유하지 않게 한다. 버전/저장 상태/복구 안내는 구분된 안전 영역에 둔다. 오류 경고와 임시 플레이는 장식으로 숨기지 않는다.

## 아트·코드 소유권과 인계

- 기존 승인 카페/술·차 도구·노트북·옷장 등 자산을 조사해 재사용한다. 새 전경 입구/문·실내 구성/필요 소품은 Codex가 Aseprite+공식 PixelLab native 생성·마감. 특정 버전 오독 재발 금지: 현재 공식 설치 숫자와 실생성 성공 증거를 따로 기록한다.
- 코디네이터/Codex는 새 ArtSource/cafe-title-2026-11-18/** 소스·PNG·프리뷰·manifest만 편집한다. Claude는 TitleView/TitleIntro 및 필요한 UI/임포트/관련 검사/별도 빌드 담당. Prototype/Coop2P와 기존 최종 아트 원본은 보존한다.
- 실내 배치 계약은 `layout.json`: 기준 화면 1920x1080, 정규화 좌표는 **좌상단 (0,0), 우하단 (1,1)**. asset ID, canvas, rect, pivot, 레이어 순서, 클릭 polygon/rect, 라벨 anchor, 입구 door hinge/threshold, 각 feature ID를 명시한다. 서로 다른 좌표계를 혼용하지 않는다.
